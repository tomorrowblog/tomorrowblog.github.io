自建安卓消息推送与通知服务- Gotify

发表于2026-01-11|更新于2026-11-03|自建服务
|总字数:2434|阅读时长:10 分钟|浏览量:

大家好，我是小明同学。

做安卓机友，有时候真的挺心累的。

尤其是想给自己的服务器、NAS 或者跑的脚本搞个“消息推送”的时候。

隔壁 iOS 用户有个神器叫 Bark，链接一填，消息秒到。

而我们呢？

❌ 接入微信/钉钉机器人？ 门槛越来越高，还得实名认证，时不时还给你限个流。
❌ 用邮件？ 实时性太差，等看到邮件，服务器可能都挂了半小时了。
❌ 依赖 FCM (谷歌推送)？ 在国内的网络环境下，这就意味着得常年挂着梯子，耗电不说，连接还时不时抽风。

我就想要一个简单、干净、实时的推送服务，怎么就这么难？

直到我遇见了它 —— Gotify。

用了一周，我只想说四个字：相见恨晚。

如果你也是喜欢折腾的“自托管（Self-hosted）”玩家，这款工具绝对能让你神清气爽。

今天就带大家看看，这个只有几 MB 的小工具，是怎么解决安卓推送老大难问题的。

01 🚀 为什么是 Gotify？(不仅仅是“安卓版 Bark”)

简单说，Gotify 就是一个完全属于你自己的消息推送服务器。

很多开源软件功能强大，但吃资源也厉害。Gotify 不一样，它是用 Go 语言写的，极其轻量。

它最大的优势就三个词：私有、实时、极简。

✅ 私有 没有广告，没有第三方窥探。你的数据，只在你的服务器和你的手机之间流动。
✅ 实时 基于 WebSocket 连接，服务器端一发，手机端毫秒级响应。
✅ 极简 没有复杂的依赖，不用配臃肿的数据库，默认 SQLite 就够了。

对于我们这种有“数据洁癖”的极客来说，这种完全掌控的感觉，真的太棒了。

03 📱 手机端体验：省电到令人发指

服务端搭好了，手机端怎么收？

直接去Google play商店或者 GitHub 下载 Gotify 的安卓 APP。

GitHub地址：https://github.com/gotify/android/releases

我们将这个 apk 下载好，在要接收消息的 android 手机上安装即可。安装包仅仅 6.75MB

如果不能下载，可以通过网盘分享的文件：Gotify.apk
链接: https://pan.baidu.com/s/16Z3tLCDyu5Ys-kJJ5MsSlQ?pwd=hkve 提取码: hkve

安装好后启动 app，我们输入对应的 server 地址，以及用户名和密码，然后登录就行

到这一步，我们要接收消息的客户端也安装好了。

很多同学担心自建推送会耗电。

实测下来，Gotify 的 APP 非常克制。因为它保持的是一个单一的长连接（WebSocket），不需要频繁唤醒系统。

在电池优化里把它设为“无限制”，它就能安安静静地在后台待机，耗电量几乎可以忽略不计。

04 🔔 万物皆可推 (解锁三个硬核场景)

服务跑起来了，怎么用呢？

Gotify 的逻辑简单到令人发指。它不需要你会写复杂的代码，只要能发 HTTP 请求的地方，就能用它。

这里分享三个我最常用的场景：

场景一：NAS 下载任务通知 🎬 我是极空间用户，以前下载任务完成了不知道。现在写个简单的脚本，下载完自动发一条 Gotify 消息：

“老板，电影下好了，回家就能看。”

场景二：服务器状态报警 🚨 利用简单的 curl 命令，配合监控脚本。 CPU 占用超过 90%？磁盘空间不足？SSH 有人尝试暴力破解？ 手机直接弹窗震动，优先级设为 High（高），半夜都能把你叫醒处理故障。

场景三：库存与价格监控 📉 如果你有写爬虫监控显卡库存、机票价格的习惯，Gotify 是最好的通知渠道。因为它延迟极低，抢购的时候快人一步。
